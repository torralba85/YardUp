# A LOT MORE landing redesign

Date: 2026-09-05. Status: shipped. This is the **implementation record** for the landing redesign — what
was built, how it behaves, and how it was validated. The design *system* it established is
[`design-system.md`](./design-system.md), which is the source of truth.

## Direction and scope

Andrew authorized a complete redesign with freedom to replace the existing palette, typography, and landing design system. The page uses a bright architectural exhibition direction: a miniature parcel, orange backyard home, oversized Space Grotesk display type, Manrope body, and chalk/carbon/orange surfaces. All styling lives in `components/landing/lot-more/LotMoreLanding.module.css`; the studio and authentication retain their existing styles (see [`product-surfaces.md`](./product-surfaces.md)).

## Page and behavior

- Hero: property address entry and three keyboard/touch-selectable illustration states (today, footprint, possibility). Responsive WebP artwork is rendered as HTML images, with CSS crossfades and no WebGL dependency. This is an illustrative transition, not an interactive surveyed 3D model or automatic orbit.
- How it works: address, spatial exploration, informed next step.
- Human uses: family, income, future needs; selection changes copy and keeps the concept image explicitly illustrative.
- Numbers: server-computed conservative/market/optimistic scenarios from `calculateFeasibility`, using the existing 600 sq ft Seattle demo configuration. Costs remain fixed while rent, operating income, and payback change. Expandable assumptions disclose expense ratio, finance exclusions, and demo provenance. Artwork is not presented as that numeric parcel.
- Report: three interactive sample-summary pages, with a studio link and the current one-time price from `lib/certificate-pricing.ts`. The actual paid certificate is unchanged.
- FAQs, final address form, responsive navigation, footer, and a mobile CTA visible between the hero and closing form.
- Both forms share typed address state. Empty submission focuses its input. Valid submission mounts the existing lazy authentication gate; confirmed authentication stashes the trimmed address with `stashAddressQuery` and routes to `/studio`. Dismissal preserves the address and restores focus. Addresses never enter the URL. The landing does not request paid address suggestions while a guest types.
- The existing auth gate is rendered outside the new style wrapper to prevent the landing's heading and control styles affecting sign-in.
- Reduced motion disables entry animation and crossfades; native controls remain usable. No scroll locking or autoplay media.

## Assets

Built-in image generation produced three original images. Project assets are optimized local WebP files in `public/landing/a-lot-more/`: `parcel-after.webp`, `parcel-before.webp`, their `-mobile.webp` versions, and `backyard-life.webp`. The originals remain in the generation output folder; the production repository contains only optimized variants. A code-native SVG parcel mark is scoped to the landing favicon and identity. Exact generation prompts are in `a-lot-more-image-prompts.md`.

## Validation

- ESLint and TypeScript passed. Production Next.js build passed with `/` statically prerendered.
- Initial Playwright pass: 27 passed, 1 desktop-only skip of the mobile menu case. Covers guest gating, address privacy/preservation, validation focus, auth cancellation focus, keyboard/reduced-motion illustration controls, coordinated financial scenarios, report pages, pricing disclosure, FAQ, no initial Firebase requests, mobile menu, and overflow at 320/390/768/1024/1440 pixels.
- Focused existing unit tests: 4 files / 27 tests passed for address handoff, authentication gate, feasibility, and finance. New landing handoff tests: 2 passed.
- Live Chrome review inspected desktop and phone layouts and the full desktop page. No production deployment or authenticated live parcel lookup was performed.
- Final check results and any full-suite limitations are recorded in the conversation handoff.

## Local preview

Run `npm run dev -- -p 4530`, then visit `http://localhost:4530`. No credentials are required to inspect the landing or demo entry. Actual sign-in follows the repository's existing Firebase/App Check local requirements.

## Follow-ups from the 2026-09-05 source-of-truth pass

- The old Blue Hour landing (`components/landing/nocturne/`), its Remotion composition
  (`remotion/nocturne/`) and the `ln-*` tokens in `app/globals.css` were deleted. `LandingAuthGate`
  moved to `components/landing/LandingAuthGate.tsx`, and the "landing ships no Firebase" invariant test
  was ported to `LotMoreLanding.firebase-free.test.ts`.
- `SiteFooter` lost its `tone="dark"` branch, which referenced the deleted `ln-*` tokens and had no
  callers.
- **Accessibility fix:** the landing focus ring was `outline: 2px solid currentColor` at
  `outline-offset: 5px`. Because the ring is drawn outside the control, on the parent ground, every
  light-labelled control (`.darkButton`, the sticky CTA, pressed segmented controls) painted a chalk
  ring on the chalk page — 1.00:1, an invisible keyboard focus indicator. The ring is now pinned to the
  ground: carbon on chalk and orange, chalk inside the carbon numbers section.
- Measured contrast surfaced one trap worth repeating: **orange on chalk is 2.83:1 and fails AA**.
  Orange is a fill colour on light ground, never text.
